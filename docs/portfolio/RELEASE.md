# Local portfolio release scope

NEXUS is a reproducible, single-host supply-chain decision demonstration. It uses synthetic data and mock purchase effects. The default path needs no Docker, provider key, or paid API.

## What is ready to show

| Stage | Demonstrated behavior |
| --- | --- |
| Data | Contract validation, quarantine, point-in-time dbt Gold tables, and source lineage. |
| Forecasting | A checksum-verified seasonal champion; a learned challenger remains out of service after failing promotion checks. |
| Decisioning | Constrained replenishment proposals with independent feasibility and simulated scenarios. |
| Control | Separate planner and approver roles, exact recommendation fingerprint binding, expiry, audit, and idempotent **mock** execution. |
| Feedback | Durable simulated outcomes, a local incident lifecycle, and a separate connected source-to-plan mode. |
| Explanation | A cited, read-only reference assistant; an optional digest-pinned local model with governed tools and fictional documents. |

The interactive demo's fresh data-quality run and frozen champion artifact have **separate provenance**. The [connected runtime](CONNECTED_RUNTIME.md) builds a new forecast from its own validated Gold snapshot; it does not relabel the frozen scientific result.

The [local verification record](VERIFICATION.md) reports the latest observed 22/22 workflow checks, 189 dbt checks, and feasible OPTIMAL plan. These observations are bound to the tested source and environment. A future public commit needs its own Actions run. The [five-minute demo](DEMO.md) and [case study](CASE_STUDY.md) are the shortest review route.

## Boundaries

Demo personas do not verify a real person's identity. Orders and outcomes are simulated; cost and fill-rate figures are not customer savings. The reference assistant and installed model cannot approve or execute. The local notification journal is not external paging. The original distributed G2-G7 production, scale, recovery, soak, and prospective model-switch gates remain open. See the [security boundaries](SECURITY.md) before changing deployment settings.
